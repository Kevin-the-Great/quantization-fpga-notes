# DiTPA 组会提纲：从动作规划冗余到加速架构

主论文：DiTPA，ISCA 2026。当前为**准备提纲**，依据[已核实摘要与代码](../notes/ditpa-2026.md)组织问题；论文全文中的图号、公式和实验配置待补。建议约 12–15 分钟，按实际组会要求调整。

建议题目：**面向 DiT 动作规划的冗余利用与加速架构——DiTPA 阅读与讨论**。

## 报告顺序

| 页 / 时间 | 要讲的论点 | 准备的图或证据 |
|---|---|---|
| 1 / 1 分钟 | 为什么闭环动作生成值得专门分析 | 画出观测、规划、执行与再次观测的关系；标明这是一张概念图，实际执行粒度以论文为准 |
| 2 / 2 分钟 | 重复计算可能跨越动作、去噪步和模态 | 用三个时间尺度组织原文观测；取得全文后补相应图表及配置 |
| 3 / 3 分钟 | 每种复用都需要判定、状态与恢复机制 | 为三种方法填写“何时触发、缓存什么、怎样刷新、增加什么开销”，避免只介绍名称 |
| 4 / 2 分钟 | 算法省掉的计算需要硬件支持才能兑现 | 依据全文画预测器、计算阵列、调度器与存储的联系；把控制和数据两类边分清 |
| 5 / 2 分钟 | 实验结论必须绑定范围和基线 | 区分动作规划器时延、完整 VLA 时延和闭环执行指标；标注模拟与测量，并用消融拆开各项贡献 |
| 6 / 1–2 分钟 | 用一项对照解释设计选择 | HG-PIPE：缓存、依赖与流水组织；或 6Bit-Diffusion：跨步复用、刷新与低比特误差。只选一项展开 |
| 7 / 1–3 分钟 | 提出一项与我们方向有关的可检验判断 | 讨论量化后复用判据是否稳定、少步采样是否减少复用空间，以及 FPGA 缓存和调度成本 |

## 重点讨论问题

1. 姿态变化较小时，平移、夹爪或接触状态的变化是否仍可能要求重新规划？原文怎样验证和恢复？
2. 复用改变中间分布后，原来的量化尺度与重构统计是否仍适用？
3. 实际节省的计算量是否覆盖缓存、判定与刷新成本？哪些地方可能受存储端口或带宽限制？
4. 如果把视觉/语言编码重新纳入计时，动作规划器的优化能转化为多少整体收益？需要哪些测量才能回答？

这些问题是阅读和后续实验的任务，不是 DiTPA 已经为我们的配置证明的结论。初筛阶段不将摘要中的加速倍数直接放入与本项目的性能对比图。
